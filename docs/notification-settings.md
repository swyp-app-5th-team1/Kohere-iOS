# 알림 설정 동작 정책

설정 > 알림 화면의 API, iOS 권한, 토글 표시 기준을 함께 유지하기 위한 문서다.
대상은 채팅 알림 한 항목이며 수신 방법(푸시/이메일) 섹션은 현재 범위에 포함하지 않는다.

## 데이터와 책임

- `NotificationSettingFeature`: 페이지 조회·저장 상태, 권한에 따른 표시, 사용자 의도, 실패 팝업 문구.
- `UserClient → UserRepository → UserRouter → NetworkService`: 인증된 GET/PATCH와 공통 응답 처리. 기존 인증 갱신/오류 처리를 사용한다.
- `PushNotificationClient`: 기기의 현재 iOS 알림 권한 조회, 예외적인 최초 권한 요청, 시스템 알림 설정 열기.
- `MoreFeature`: 설정에서 알림으로 이동, 팝업의 재시도·돌아가기·설정 이동 액션 전달.
- `RootFeature`: 공용 팝업 표시, 로그인/앱 복귀 후 APNs 및 FCM 기기 등록.

서버 설정과 기기 권한은 별개다. `chatPushEnabled`는 같은 계정의 모든 기기에 적용되지만 iOS 권한은 해당 기기에만 적용된다.
시스템 권한 거절을 이유로 PATCH false를 보내거나 FCM 토큰을 삭제하지 않는다.

## API

같은 경로 `/api/v1/users/me/notification-preferences`를 사용한다.

| 동작 | 요청 | 성공 시 기준 |
| --- | --- | --- |
| 조회 | GET, 본문 없음 | `data.chatPushEnabled` |
| 변경 | PATCH, `{"chatPushEnabled": true 또는 false}` | 응답의 `data.chatPushEnabled`로 확정 |

설정 이력이 없으면 서버 기본값은 true다. 클라이언트는 첫 응답 전 true를 임의로 채워 넣지 않는다.
`fetchCurrentUser`나 앱 시작 시점에 이 설정을 미리 조회하지 않는다.

## 페이지 진입과 복귀

1. 페이지 진입 시 GET과 iOS 권한 조회를 동시에 시작한다.
2. 값을 모르는 동안 카드 전체를 하나의 스켈레톤으로 표시한다. 텍스트·토글 모양의 개별 placeholder는 표시하지 않는다. 별도의 최소 지연, 강제 실패, 인라인 재시도 버튼은 없다.
3. 기기 권한이 거절/미결정으로 확인되면 서버 응답 전에도 OFF를 표시할 수 있다.
4. GET 실패 시 공용 액션 팝업에서 **다시 시도 / 돌아가기**를 제공한다.
   재시도는 실제 GET과 권한 조회를 다시 실행하고, 돌아가기는 설정 페이지로 돌아간다.
5. 알림 화면이 열린 상태에서 앱이 포그라운드로 복귀하면 GET과 권한을 다시 확인한다.
   이미 진행 중인 같은 조회는 중복 실행하지 않는다. 이전 요청 세대의 응답은 무시한다.
6. PATCH 진행 중 복귀하면 권한만 우선 확인하고 GET은 PATCH 완료 이후로 미룬다.

실제 네트워크 대기/타임아웃은 기존 공통 네트워크 설정을 따른다.
녹화용 3초 지연과 강제 초기 조회 실패는 제거했다.

## 토글 표시와 권한 정책

`표시값 = 기기가 알림을 허용함 && (저장 중인 사용자 선택값 ?? 마지막 서버 확인값)`

| iOS 상태 | 표시/탭 동작 |
| --- | --- |
| authorized / provisional / ephemeral | 서버 값으로 표시. 탭하면 PATCH |
| denied | OFF. 탭하면 시스템 설정 안내 팝업 |
| notDetermined | OFF. 탭하면 최초 권한 요청 후 실제 권한을 재확인 |
| unknown | OFF. 탭하면 권한 확인 실패 안내 |

provisional/ephemeral은 iOS가 허용하는 제한된 알림 수신 상태이며 일반 허용과 전달 방식이 같다는 뜻은 아니다.
로그인 및 온보딩 완료 후 권한을 요청하는 기존 흐름을 유지하므로 notDetermined는 예외 경로다.

권한 거절 안내는 **토글을 눌렀을 때만** 띄운다.

- 한국어: “이 기기에서 Kohere 알림이 꺼져 있어요.\n채팅 알림을 받으려면 설정에서 알림을 허용해 주세요.”
- 영어: “Notifications are turned off for Kohere on this device.\nAllow notifications in Settings to receive chat alerts.”
- 액션: **취소 / 설정으로 이동** (`Cancel / Open Settings`).
- 설정 이동을 선택해야 iOS의 Kohere 알림 설정을 연다. 이동 실패 시 안내하고 다시 조작할 수 있도록 복구한다.

이 화면에서 명시적으로 켜려다 시스템 설정으로 이동한 경우에만, 복귀 후 권한과 GET 결과가 모두 확인되면 켜기 동작을 이어간다.
이미 서버 true면 PATCH를 생략한다. 허용하지 않고 돌아오거나 조회에 실패하면 이어갈 의도를 지운다.
일반적인 앱 복귀나 다른 경로에서의 권한 허용만으로 서버 false를 자동 변경하지 않는다.

## 토글 저장

1. 탭한 값을 즉시 화면에 적용한다(낙관적 업데이트).
2. PATCH 응답 전까지 추가 탭을 막는다. 저장 중에는 스켈레톤으로 교체하지 않는다.
3. 성공하면 요청값이 아닌 **서버 응답값**으로 확정한다.
4. 실패하면 마지막 확인값으로 되돌리고 공용 안내 팝업을 띄운다.
5. 응답만 유실되고 서버에는 반영됐을 가능성에 대비해 GET을 다시 실행한다.
   이 조회 중에는 마지막 확인값을 유지하고 추가 변경은 막는다.
6. 복구 GET까지 실패하면 재시도/돌아가기 액션 팝업으로 전환한다.

취소된 요청은 늦은 결과나 실패 팝업을 보내지 않는다. 페이지가 path에서 제거되면 TCA가 해당 페이지의 효과를 취소한다.

## 푸시 등록과 화면 문구

로그인된 사용자의 앱 복귀 시에는 권한 팝업을 다시 요청하지 않고 현재 권한만 읽는다.
허용되어 있으면 기존 APNs 등록 및 FCM 스트림 구독을 재개한다.
동일 observer ID로 중복 구독을 취소하고, 토큰은 기존 멱등 기기 등록 API에 전달한다.
로그아웃 시 관찰/기기 등록 효과를 취소하고 이후 토큰 액션도 인증 상태로 걸러낸다.

- 임차인: **임대인 메시지 / Landlord Messages**
- 임대인: **임차인 메시지 / Tenant Messages**
- 페이지 제목, 섹션 제목, 오류 및 권한 안내는 기존 한국어/영어 String Catalog를 사용한다.
- 토글 ON은 `basePrimary #F36012`, OFF는 `gray400 #A6ABB7`.
- 현재 카드 스켈레톤과 공용 팝업 스타일을 사용한다. 추가 디자인 답변에 따라 시각 표현과 문구를 조정한다.

## 검증 범위

`NotificationSettingFeatureTests`에서 실제 서버와 시스템 설정 대신 주입한 응답으로 아래 정책을 검증한다.

- 초기 조회 전 스켈레톤, 권한 거절 시 OFF 및 서버 값 보존.
- 낙관적 표시, 중복 탭 차단, 응답값 확정, 실패 복구 및 재조회.
- PATCH 중 복귀 시 GET 순서 보장.
- 일반 복귀와 명시적인 설정 이동 후 복귀의 구분.
- 최초 권한 요청 예외 및 푸시 등록 위임.
- 초기 조회 실패의 재시도/돌아가기 액션, 재조회 및 이전 응답 무시.

시스템 설정 앱 왕복, 실제 계정의 GET/PATCH, 여러 기기의 동기화, 실제 FCM 수신은 별도 실행 확인이 필요하다.
